# Лабораторна робота № 1: Розгортання середовища автоматизації тестування

**Дисципліна:** Автоматизація тестування  
**Спеціальність:** F2 «Інженерія програмного забезпечення» · 4 курс  
**Виконавець:** milunchik (студент 4 курсу)  
**Варіант:** Обчислення середнього арифметичного масиву чисел; відхилення порожнього масиву

---

## 📋 Опис проєкту

Проєкт містить розгорнуте середовище для автоматизованого тестування на базі **Node.js**, **TypeScript** та фреймворку **Vitest**, а також налаштовані лінтер **ESLint** та форматувальник **Prettier**.

У проєкті реалізовано:

1. **Базовий модуль:** Конвертер температур `src/temperature.ts` та його модульні тести `tests/temperature.test.ts`.
2. **Індивідуальний модуль (Частина 2):** Функція обчислення середнього арифметичного `src/average.ts` та її модульні тести `tests/average.test.ts`.

## 🚀 Встановлення та запуск

### 1. Встановлення залежностей

```bash
npm install
```

### 2. Запуск тестів

```bash
# Одноразовий запуск усіх тестів
npm test

# Запуск тестів у режимі спостереження (watch mode)
npm run test:watch
```

### 3. Вимірювання покриття коду (Coverage)

```bash
npm run coverage
```

Звіт у форматі HTML буде збережено в директорії `coverage/index.html`.

### 4. Перевірка якості коду (Linting & Formatting)

```bash
# Перевірка коду за допомогою ESLint
npm run lint

# Автоматичне форматування коду за допомогою Prettier
npm run format
```

## Лабораторна робота №2 — варіант 12

У `src/order.ts` додано `calcInstallment(total, months)` із параметризованими
тестами у `tests/order.test.ts`. Модулі та тести лабораторної №1 збережено.

Прийняті припущення: проста надбавка до початкової суми становить 2%, 4% і 8%
для 3, 6 і 12 місяців відповідно; місячний платіж округлюється до двох десяткових
знаків за правилом «половину вгору». Вхідна сума має бути скінченним невід’ємним
числом. Докладний контракт, коди помилок і фактичні результати наведено в
[документації лабораторної №2](docs/lab2/README.md).

```bash
npm test
npm run lint
npm run typecheck
npm run format:check
npm run coverage
```

`npm run coverage` також перевіряє мінімум 90% покриття гілок безпосередньо
функції `calcInstallment`, використовуючи межі функції та лічильники у JSON-звіті.
Пороги лабораторної №1 залишено: рядки ≥80%, гілки ≥80%, функції 100%.

Вихідна методичка лабораторної №2 не була доступна. Тому чотири функції
наданого прикладу (`calcSubtotal`, `calcDiscountRate`, `calcShipping`,
`calcOrderTotal`) та точний експеримент із `calcOrderTotal` ще очікують її тексту.
Цей стан не означає повного завершення лабораторної №2. Дії з GitHub виключено
за вказівкою користувачки.
