Мета роботи
Опанувати дисципліну розроблення через тестування: розробити модуль з нуля за циклом Red – Green – Refactor, фіксуючи кожен крок окремим комітом; навчитися виконувати рефакторинг під захистом тестів і оцінювати вплив підходу на структуру отриманого коду.

Частина 1: спільне розроблення модуля тарифікації паркування за циклом TDD. Викладач веде, здобувачі повторюють кожен крок

Ключова вимога до роботи
Оцінюється не лише кінцевий код, а й історія його створення. Кожен крок циклу фіксується окремим комітом із префіксом у повідомленні:
git commit -m "red: відхиляє від’ємну тривалість"
git commit -m "green: перевірка тривалості"
git commit -m "refactor: винесено валідацію в окрему функцію"
Робота, подана одним комітом із готовим кодом і тестами, не зараховується незалежно від якості результату: вона не доводить застосування підходу.

Цикл 4. Наступні години
Red
Порахуймо очікувані значення вручну. Для 61 хвилини: перша година – 30, плюс одна розпочата година – 20, разом 50. Для 120 хвилин: розпочатих годин понад першу так само одна, отже, теж 50. Для 121 хвилини – дві, тобто 30 плюс 40, разом 70.
it.each([
  { minutes: 61,  expected: 50 },
  { minutes: 120, expected: 50 },
  { minutes: 121, expected: 70 },
  { minutes: 180, expected: 70 },
])('тривалість $minutes → $expected', ({ minutes, expected }) => {
  expect(calcParkingFee(minutes)).toBe(expected);
});
Green
if (minutes <= 15) return 0;
if (minutes <= 60) return 30;
 
const extraHours = Math.ceil((minutes - 60) / 60);
return 30 + extraHours * 20;
Refactor
Магічні числа в коді ускладнюють його читання й зміну. Виносимо їх у константи.
const FREE_MINUTES = 15;
const FIRST_HOUR_FEE = 30;
const EXTRA_HOUR_FEE = 20;
 
export function calcParkingFee(minutes: number, options: ParkingOptions = {}): number {
  if (!Number.isInteger(minutes) || minutes < 0) {
    throw new Error('INVALID_DURATION');
  }
  if (minutes <= FREE_MINUTES) return 0;
  if (minutes <= 60) return FIRST_HOUR_FEE;
 
  const extraHours = Math.ceil((minutes - 60) / 60);
  return FIRST_HOUR_FEE + extraHours * EXTRA_HOUR_FEE;
}
Запускаємо тести після рефакторингу – усі зелені. Ми змінили структуру коду й одразу переконалися, що нічого не зламали.
Цикл 5. Максимум за добу
Red
З’ясуємо, коли спрацьовує обмеження. Формула дає 30 плюс 20 помножити на кількість розпочатих годин понад першу. Двісті гривень досягаються, коли доданок сягає 170, тобто при 8,5 годинах – отже, при дев’яти розпочатих годинах сума становитиме 210 і має бути обмежена до 200. Дев’ять розпочатих годин понад першу – це тривалість понад 540 хвилин.
it.each([
  { minutes: 540, expected: 190 },
  { minutes: 600, expected: 200 },
  { minutes: 1440, expected: 200 },
])('обмеження добової плати: $minutes → $expected',
  ({ minutes, expected }) => {
    expect(calcParkingFee(minutes)).toBe(expected);
  });
Green
const DAILY_CAP = 200;
 
const fee = FIRST_HOUR_FEE + extraHours * EXTRA_HOUR_FEE;
return Math.min(fee, DAILY_CAP);
Цикл 6. Нічний тариф
Red

  { minutes: 121, expected: 35 },
  { minutes: 600, expected: 100 },

Зверніть увагу: нічний тариф застосовується після обмеження добової плати. Якби ми зробили навпаки, результат для довгого паркування відрізнявся б. Порядок операцій – предмет уточнення в замовника, і тест його фіксує.

Цикл 8. Заокруглення та підсумковий рефакторинг
Red
it('заокруглює результат до копійок', () => {
  // 45 хв, ніч, вихідний: 30 / 2 * 0.8 = 12
  expect(calcParkingFee(45, { night: true, weekend: true }))
    .toBe(12);
 
  // 121 хв, ніч, вихідний: 70 / 2 * 0.8 = 28
  expect(calcParkingFee(121, { night: true, weekend: true }))
    .toBe(28);
});
Green і Refactor
Додаємо заокруглення й одночасно розділяємо функцію: базовий тариф і застосування знижок – це дві різні відповідальності.
const FREE_MINUTES = 15;
const FIRST_HOUR_FEE = 30;
const EXTRA_HOUR_FEE = 20;
const DAILY_CAP = 200;
const NIGHT_RATE = 0.5;
const WEEKEND_RATE = 0.8;
 
const round2 = (n: number): number => Math.round(n * 100) / 100;
 
function assertValidDuration(minutes: number): void {
  if (!Number.isInteger(minutes) || minutes < 0) {
    throw new Error('INVALID_DURATION');
  }
}
 
export function calcBaseFee(minutes: number): number {
  if (minutes <= FREE_MINUTES) return 0;
  if (minutes <= 60) return FIRST_HOUR_FEE;
 
  const extraHours = Math.ceil((minutes - 60) / 60);
  return Math.min(
    FIRST_HOUR_FEE + extraHours * EXTRA_HOUR_FEE,
    DAILY_CAP,
  );
}
 
export function applyRates(fee: number, options: ParkingOptions): number {
  let result = fee;
  if (options.night) result *= NIGHT_RATE;
  if (options.weekend) result *= WEEKEND_RATE;
  return result;
}
 
export function calcParkingFee(
  minutes: number,
  options: ParkingOptions = {},
): number {
  assertValidDuration(minutes);
  return round2(applyRates(calcBaseFee(minutes), options));
}
Підсумковий рефакторинг виконано на повністю зеленому наборі приблизно з двадцяти тестів. Розбиття монолітної функції на три зайняло дві хвилини й було безпечним, бо кожен крок одразу перевірявся.
Крок 9. Аналіз результату
Подивіться на отриманий код і зафіксуйте у звіті відповіді на такі питання:
скільки рядків продуктового коду ви написали і скільки з них не покрито жодним тестом;
який показник покриття гілок дає набір, і чи довелося щось дописувати для досягнення порогів;
скільки разів ви виконували крок Refactor і чи ламалися при цьому тести;
чи виникали моменти, коли хотілося написати більше коду, ніж вимагав поточний тест.

Частина 2. Завдання для самостійного виконання
Розробіть модуль за своїм варіантом, суворо дотримуючись циклу TDD. Вимоги подані у вигляді нумерованого переліку – реалізуйте їх по одній, у зазначеному порядку.
Вимоги до подання
щонайменше шість завершених циклів Red – Green – Refactor;
кожен крок зафіксовано окремим комітом із префіксом red, green або refactor;
щонайменше два коміти з префіксом refactor;
покриття гілок не нижче 90 %;
перевірка межових значень для кожного числового порога;
щонайменше один параметризований тест.
Вар.
Модуль і вимоги
1
Тарифікатор доставки: безкоштовно від 1000 грн; до 5 кг – 50 грн; кожен наступний розпочатий кілограм – 10 грн; максимум 300 грн; експрес – подвійний тариф.
2
Калькулятор лікарняних: перші 5 днів – 60 % середньої зарплати, з 6-го по 10-й – 80 %, далі – 100 %; максимум 30 днів.
3
Нарахування пені за прострочення: 0,1 % на день, пільговий період 3 дні, максимум 50 % від суми боргу.
4
Тарифікатор таксі: посадка 40 грн, перші 3 км включено, далі 12 грн за км, нічна надбавка 25 %, мінімальна поїздка 80 грн.
5
Калькулятор знижки за стажем клієнта: до року – 0 %, 1-3 роки – 5 %, 3-5 років – 10 %, понад 5 – 15 %; подвоюється в день народження.
6
Розрахунок вартості друку: чорно-білий аркуш 2 грн, кольоровий 8 грн, від 100 аркушів знижка 10 %, від 500 – 20 %; двосторонній друк дешевший на 15 %.
7
Калькулятор комісії переказу: 1 % від суми, мінімум 5 грн, максимум 150 грн; для сум понад 50 000 потрібна додаткова перевірка – виняток.
8
Тарифікатор мобільного зв’язку: 100 хвилин включено, далі 0,5 грн за хвилину; міжнародні – 3 грн; абонплата 150 грн.
9
Розрахунок вартості оренди: доба 800 грн, від 7 діб знижка 10 %, від 30 – 25 %; застава 2000 грн повертається.
10
Калькулятор балів студента: лабораторні, контрольні, проєкт із ваговими коефіцієнтами; переведення в шкалу ЄКТС; відхилення значень поза діапазоном.
11
Тарифікатор електроенергії: до 100 кВт/год – 1,68 грн, понад – 2,64 грн; нічний тариф удвічі дешевший; абонплата 30 грн.
12
Розрахунок вартості страховки: базовий тариф за віком авто, надбавка за стаж водія менше 3 років, знижка за безаварійність до 30 %.
Кожен варіант навмисно містить кілька числових порогів і взаємодію правил між собою. Розбийте специфікацію на окремі вимоги самостійно й реалізуйте їх по черзі – саме це є частиною завдання.
Взаємне рецензування
Кожен здобувач переглядає історію комітів однокурсника й відповідає письмово на три питання:
чи відповідає послідовність комітів циклу, чи зустрічаються коміти, де продуктовий код з’явився раніше за тест;
чи був код на кроці Green справді мінімальним, чи одразу писалася узагальнена реалізація;
чи виконувався рефакторинг, і які саме покращення структури було зроблено.

Контрольні питання
Назвіть три кроки циклу TDD і сформулюйте правило для кожного.
Чому важливо побачити, як тест падає, перш ніж писати код? Які дві причини можуть зробити щойно написаний тест зеленим?
Чому на кроці Green пишуть мінімальний код? Наведіть приклад із власної роботи.
Чому рефакторинг виконують лише на зеленому наборі тестів?
У якому циклі показової частини знадобився рефакторинг і що саме було покращено?
Поясніть, чому порядок застосування нічного тарифу й обмеження добової плати впливає на результат.
Що означає твердження «TDD дає зворотний зв’язок про архітектуру»? Чи відчули ви це під час роботи?
Чому робота, подана одним комітом, не зараховується, навіть якщо код і тести якісні?
Наведіть три класи задач, для яких TDD погано підходить.
Яким є найкращий сценарій застосування TDD у промисловій роботі і чому?

Типові помилки
Написання повної реалізації на кроці Green замість мінімальної.
Пропуск кроку Refactor: код накопичує магічні числа й дублювання.
Написання тесту, який проходить одразу – ознака того, що він нічого не перевіряє.
Один великий коміт наприкінці роботи замість покрокової історії.
Обчислення очікуваних значень формулою замість ручного розрахунку.
Реалізація всіх вимог одразу з подальшим написанням тестів «навздогін».
Відсутність тестів на межові значення числових порогів.
